# Epistle 045 — The Face Is Configuration, Not an Agent // Gravel Record

## Gold (earned weight)

1. **Intake depth is a named configurable axis on Hermes — and naming it is what forces Option B.**
   *Because:* the corpus already carries two depths as two facts — §6.12 gives Hermes hermeneutic carriage (task arrives, Hermes routes), §6.12a gives Ari "holds the conversation at dojo depth until telos-readiness." What the corpus does *not* do is name these as two settings of *one* axis on *one* agent. The epistle's move — "same agent, same hermeneutic obligation (§6.12), different depth at which meaning gets carried" (line 18) — collapses the Hermes-carriage / Ari-cultivation pair into a single parameter. That collapse is new and it is load-bearing: it is the premise the whole Option-B argument stands on. Without the axis, "a separate intake agent" and "Hermes at a different depth" are not even commensurable; with it, they are two values of the same knob and the cheaper one wins. The axis is the gold. (Caveat amended below: only two of its three settings are independent — the third is the generalization re-instanced, sorted to gravel.)

2. **The sock-puppet honesty constraint is a clean new application of §1.5.**
   *Because:* §1.5 is stated about `server` and `200 OK` — borrowed role-vocabulary carries the obligation structure of the practice it is borrowed from. The epistle applies the same machine to personas: "a face that pretended to be a human would import the social obligations of a person Anima is not; a face that is openly Anima-in-a-persona imports none" (line 36). This is §1.5 read at the persona layer — disguise borrows a human role (and its obligations); declared register borrows none. The application is new (§1.5 never reached personas) and load-bearing (it constrains what any face may be — declared register, never disguise). The warrant is present and exact. Faithful §1.5 extension.

## Gravel (dropped)

1. **"The generalization is not a new claim. It is what §6.12a already commits to, read at one more context."**
   *Reaching toward:* once a face is config not agent, any host context can configure one — a Slack assistant is "the face Anima wears in that context," same three parts as Ari fitted to a different surface (lines 13–14).
   *Because:* §6.12a names exactly one face on exactly one surface — "the face the system wears **in the dojo** before the relay chain engages." It stakes the face/agent *distinction* (the §6.1 mechanism: same information-poet harm, different material → face, not constellation entry). The distinction is frozen. The universal quantifier — *any* host can configure *a* face — is not in §6.12a; it is added by this epistle. The tell is internal: line 50's own Open concedes "the generalization to arbitrary host contexts and the intake-depth axis are new." Line 14 says the generalization "is not a new claim"; line 50 says it is. Both cannot hold. The generalization is real construction worth doing — but it is construction *on top of* §6.12a, not a reading *of* §6.12a, and staking it as already-committed is the founder-exemption move §3.3a names (reframing new extension as clarification of frozen material). Drops as-presented. It can re-earn weight if restaked honestly as a derivation-with-a-new-premise, or as a §6.12a amendment — which is the question line 50 correctly flags and then the body answers the wrong way.

2. **The "face-configured" third intake depth.**
   *Reaching toward:* a third setting on the depth axis — "an external host. Hermes adopts a named persona... cultivating or shallow depending on the face's purpose" (line 24).
   *Because:* the first two settings (shallow CLI / cultivating dojo) are the genuine collapse that earns Gold #1 — each names a depth the corpus already evidences. The third is not an independent depth. By its own description it is *cultivating or shallow* — i.e. one of the first two — applied to a new host. It adds no new value to the axis; it adds the generalization (gravel #1) wearing the axis's clothing. The three-depth model is therefore a two-depth axis plus one re-instancing of the contested generalization. Counting it as a third setting double-counts the generalization as if the axis independently produced it.

3. **"Option B is the only reading that survives §6.12a."**
   *Reaching toward:* a separate intake agent re-introduces the face/agent confusion §6.12a resolved and breeds a §5.1 mesh "one face at a time" (lines 28–32), so Hermes-absorbs-intake is forced, not chosen.
   *Because:* the because-chain is valid but the premise is mislabeled. The §5.1 mesh-reassembly argument only bites *if* every host breeds its own intake agent — which is true only *if* faces generalize to arbitrary hosts. So Option B is forced by §6.12a **plus the generalization (gravel #1)**, not by §6.12a alone. "The only reading that survives §6.12a" charges the conclusion to the frozen section while the load is actually carried by the new construction. The §5.1 invocation itself is sound (peer-to-peer intake agents would be the mesh §5.1 rules out); the overreach is the attribution. Re-presented as "the only reading that survives §6.12a-plus-the-generalization," this would be a fair derivation — and would correctly expose that the whole Option-B result is downstream of the contested premise, not independent support for it.

4. **Socrates-the-name "is available as a face" because the eviction freed it.**
   *Reaching toward:* §6.12 records Socrates tried-and-superseded as a name for the front door; "that eviction is exactly what makes Socrates available as a *face*"; "the name's own history demonstrates the face/agent distinction" (line 40).
   *Because:* the *reading of the eviction* is faithful — §6.12/§16.3 do say Socrates was superseded as a Hermes name because "Socrates teaches within a tradition; Hermes carries meaning across traditions," i.e. the teaching/cultivation register was evicted from the front-door agent. No overreading there. But the corpus already re-homed that evicted function: §6.12a states "§6.12's Socrates-rule-out evicted the cultivation/teaching function from Hermes... **Ari carries it**." The function went to Aristotle. The epistle's further step — therefore the *name* Socrates is available to wear as a face — is name-recycling illustration, not architecture. It demonstrates nothing the §6.1 mechanism in §6.12a/§033 doesn't already demonstrate; it decorates the distinction with a tidy etymological coincidence. Drops as load-bearing evidence, kept (if anywhere) as illustration. The body even concedes the corpus "stakes the mechanism... and stops there; which character fits CL's Slack is a human call" (line 38) — which removes Socrates from the staked layer entirely.

## Tensions (open)

1. **Derivation vs. amendment — the epistle's own line 50, unresolved by the body and answered the wrong way.** Line 50 asks the exact right question: is this a derivation from §6.12a or a §6.12a amendment? The face/agent *distinction* is §6.12a's (derivation-safe). The *generalization to arbitrary hosts* and the *intake-depth axis as a named configurable parameter* are new (amendment-shaped). Shitcorping's ruling: the axis (Gold #1) is a genuine new contribution that extends §6.12a without contradicting it — liquid candidate material, amendment-track if it freezes. The generalization (gravel #1) is the part that needs §6.12a to be *restaked*, not merely cited, before it can carry the Option-B weight the epistle hangs on it. The honest split is: keep the axis, demote the generalization to an explicit proposed extension, and rebuild Option B on the extension rather than on frozen §6.12a.

2. **§3.3 externality applied to config-load (line 46) is a stretch, honestly flagged.** "§3.3 externality favors a startup query — the face is pulled from the store, not pushed by the caller." §3.3 is about *validation* externality (the validator external to the validated; the append-only store both see and neither edits). Where a config is *loaded from* is not a validation question — pull-vs-push provenance is closer to §5.4 (no out-of-substrate re-assertion) or the §6a push/pull surface than to §3.3. The instinct (pull from Calliope) may well be right; the warrant cited for it is the wrong section. Held as tension rather than hard gravel because it sits in the Opens, explicitly "the corpus has not staked it" — an honest lean, not a staked claim. Flag: when this Open is taken up, re-warrant it off §5.4 / §6a, not §3.3.

3. **§9.4 trailered, never invoked in the body.** The trailer (line 52) lists §9.4 ("the system never pretends not to know what it knows"). The body's honesty argument runs entirely through §1.5 (the sock-puppet register). §9.4 would actually *strengthen* the sock-puppet claim — a face that hid it was Anima would be the "creepy" silent move §9.4 rules out — but the epistle never makes that connection. Trailer citation without a body warrant. Minor; close by either wiring §9.4 into the honesty argument or dropping it from the trailer.

4. **The Bench mirror (line 32) is apt but supporting, not independent.** "CLI is the spine; UI is a face on it" (substrate.md Bench) is frozen, and reading the intake face as the same spine-and-face pattern (Hermes the spine, the face config on it) is a genuine isomorphism. But it reinforces Option B; it does not independently establish it — it inherits whatever the generalization premise inherits. Counted toward Gold #1's support, not sorted as standalone gold.
