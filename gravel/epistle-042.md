# Epistle 042 — The Iceberg: Dojo In, Forge Out // Gravel Record

## Gold (earned weight)

1. **Dojo and forge name the two directions of knowledge flow across the Calliope boundary; an unnamed direction is ungoverned.** Dojo is the inbound face (surface → Calliope, the system capturing movement); forge is the outbound face (Calliope → surface, the system projecting movement). One efficient cause, two directions — not a new cause type. *Because:* an asymmetry with no name cannot be reasoned from (§2.5 — corpus is coordinates), so naming the outbound face is what makes the code↔Calliope relationship governable on the way out. §3 cut the inbound face (ratification, supersession, externality) and never had a counterpart question for the externality discipline on the way out. Rules out treating the code↔Calliope relationship as governed once only the inbound name exists.

2. **The generated-doc surface is pure-forge: no dojo path, authority flows one direction only.** READMEs, CLAUDE.md, API docs, agent-context docs are rendered out from canonical Calliope artifacts (build_decisions, domain_knowledge, corpus_sections, sprint_contracts), never authored in. *Because:* the distinction from authored docs is structural, not incidental — authored docs flip standing at the freeze act; generated docs never shared standing to flip. A divergent generated doc is stale rendering, not a conflicting version, so Epistle 039's standing-flip arbitration does not apply. Rules out reading a hand-authored README as canonical: it is doing dojo-direction work by convention without the ratification discipline — the doc-surface analogue of domain_knowledge's overload.

3. **domain_knowledge's overload is the asymmetry made visible: the inbound name doing duty for a relationship whose outbound name was never coined.** The code↔Calliope relationship has two halves — extract upward (dojo), materialize downward (forge); with no name for the forge direction, domain_knowledge bloats to fill the silence. *Because:* this diagnoses the bloat structurally rather than as a content problem. Rules out fixing the overload by redistributing domain_knowledge's contents — the fix is naming the forge so the asymmetry becomes governable, after which §3's inbound cut gains its counterpart question (what is the externality discipline on the way out?).

4. **Same shape across three surface types, specified at both directions, is a checkable diagnostic instrument.** Authored doc, generated doc, and code each have a dojo direction and a forge direction; specified concretely at every cell, an inconsistency would be visible. *Because:* this operationalizes §7.1 self-resonance as a test rather than an impression — any surface with a governed inbound and an unnamed outbound is the next domain_knowledge. Every forge-column cell that reads "unbuilt" marks where hand-authored convention carries load it should not.

## Tensions (open)

1. **The forge has no externality cut yet.** §3.3 requires the validator external to the validated. The dojo direction has it — ratification, the place-outside (§5.2). The forge direction has build_verification, but a green build is not a ratified claim that the code honors the because. Whether build_verification is the externality cut on the forge, or merely a test pass with no §3.2 contestable face, is open. The forge may need its own externality primitive distinct from the dojo's. Do not read build_verification as the answer. This is the epistle's best open tension and a candidate for its own epistle.

2. **The running system as a possible third surface.** Its forge is the deployment chain, distinct from the code forge; the §1.12 return-path (field_record, §4.9, Epistle 027/029/030) is plausibly its dojo half — field observation disciplining upward into Calliope. Surface count is staked as a question, not a count: the iceberg may have at least three surfaces, with deployment-forge vs. code-forge a live distinction. Leave open for extension.

3. **Which Calliope artifact types carry corpus material.** Whether epistle, gravel, and corpus-§ are distinct artifact types is Epistle 043, not here. This epistle names the directions, not the types that flow through them.
