Epistle 002 — Hermes at the Boundary
Topic: Hermes as the sole human-system contact point. Relay as a named behavior class.
Hub-and-spoke extends to the human boundary. §5.1 specifies no agent communicates directly with another. The corpus does not explicitly state this extends to human→system contact. It should be staked: Hermes is the only point at which human input enters the system. Not for routing convenience — for the epidemiological reason. Contamination caught before domain framing cannot have propagated. Every downstream agent sees the request only after Hermes has translated it into the architecture's frame. No domain agent can catch cross-domain confusion or pre-framing contamination — each agent sees the request already within their domain. Hermes at the border catches a structurally different contamination class at the structurally cheapest moment. This is not redundant with each agent doing its own hygiene. [→ §5.1, §6.12, §15.12, §15.18]
Relay — named behavior class. Telescoping (§6.15) is parallel, spatially decomposable, synthesis-requiring. There is no named behavior for sequential multi-agent response to one human request, where each stage informs the next. Proposed name: relay. A relay runner receives accumulated meaningful context, carries what is load-bearing forward, hands it to the next. The selective carry is the skill. Forwarding everything without compression is not relay — it is a tool call. Relay is a skill: identify what meaning must traverse this domain boundary, compress it, carry it, don't lose it. This is §1.16 ("knowing when to go up in detail and when to go down") operating as a structural condition: over-carry bloats the downstream agent's context; under-carry loses meaning at the boundary.
Three conditions for relay (parallel to §6.15):

The request requires reasoning across multiple distinct domains in sequence — no single agent owns the full answer.
Each stage's output is load-bearing input to the next — sequential dependency, not parallel decomposition.
The carry step is selective compression. Distinguishing condition. Without it, you have forwarding, not relay.

Relay is Hermes's and cannot be reassigned — selective compression across domain boundaries is the hermeneutic skill. Mnemosyne does not know what matters to Urania. Hermes does.
Relay completes its loop at the human. The same skill describes the final handoff. Hermes carries the system's output back to the human with the same selective compression: here is what Anima produces, here is what it cannot answer, what do you say? The human is not a passive recipient — they are the next runner. Relay is the behavior class that names both directions of Hermes's job. [→ §6.12, §6.15, §1.16]
