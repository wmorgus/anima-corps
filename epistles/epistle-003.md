Epistle 003 — Agent Execution Loop
Topic: Base execution loop as ratifiable artifact per agent. Tool vs. skill as a load-bearing distinction.
The gap. §6a specifies what agents reason from — four context tiers, three currently delivered incorrectly. It does not specify how agents reason — the procedural shape of execution. This is a genuine gap. Each agent needs an explicit, ratifiable loop definition.
Base execution loop. Best-for-now practice; not a novel claim. Five stages:
StageModeCheck inputSkillGather contextTool + SkillReason fromSkillSelf-auditSkillWrite toTool + Skill
Each agent has a ratifiable definition of how it executes each stage. The base loop creates the slots; each agent's definition fills them. Deviations from the base loop are where concept ownership (§6.5) is concretely expressed — different frozen corpus, different reasoning pattern, different artifact type. The deviation is the function, made visible.
Self-audit is not self-ratification. §3.3 requires the validator to be external to the thing validated. Self-audit is internal — preparation before the crossing, not the crossing itself. The write-to is the externalization. Loop definitions must name this distinction explicitly or agents will miscategorize their own reasoning step as governance, and the externality requirement will be misread as forbidding it.
Tool vs. skill. §6.3 names "tool set" and never defines it. The distinction is load-bearing: a tool is a callable capability — write to Calliope, retrieve by typed-edge traversal, delegate. A skill is a reasoning pattern applied — citation discipline, harm-bearer identification, selective compression (relay). Different obligation structures. A tool can be enumerated in a manifest. A skill must be practiced; it lives in the prompt and in how the agent reasons. Different failure categories: tool loss is a capability loss, detectable and patchable. Skill degradation is a reasoning obligation failure — it shows up in the harm-when-failed column (§6.5), not in a manifest diff. Currently under one word. Needs splitting. [→ §6.3, §6.5]
Tool and skill per stage. The skill at write-to is genuine citation, not schema compliance. These are different and the corpus already names the failure mode — a structurally compliant artifact with hollow rationale is indistinguishable from a genuine one without independent reconstruction (§3.16). The base loop must name this or the write-to stage becomes pure tool use and the skill disappears.
