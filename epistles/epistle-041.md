Epistle 041 — The Generative Build Procedure
Topic: How an Anima agent handed a telos doc builds a project — the run-forward face of §13.13's read-backward diagnostic.

§13.13 stakes Lakatos as a diagnostic: read the supersession record at scale, ask whether the programme generates or absorbs. Backward-looking, requires a finished record. The corpus has no forward face — no procedure the agent runs to *build* a project from a telos doc. This epistle stakes it. Components are already on record (§13.6 derivation, §13.13 belt/core, §8.6 four primitives). The procedural synthesis — wiring them into one build loop with a stopping condition and an escalation rule — is the contribution.

---

**G1 — The build loop is a procedure, not a posture.**

Agent receives telos doc. Five moves, in order.

1. *Read beneath the stated telos.* Where is the language straining, what is it reaching toward? The stated telos is a register, not the thing (§13.11 — meaning lives upstream of the register that runs). The doc says X; the agent reads for what made X necessary.

2. *Ratify the reading back.* "Here is what I think this is actually for." The reading is a commitment that crosses a boundary — it gets recorded where both parties see it and neither edits it after (rhetoric §3.20). Not silent inference (§9.4 — never act on what you know without surfacing it). The human ratifies or corrects the read before architecture is touched.

3. *Derive architecture — not choose it.* If telos is X, what must be true for X to be achievable? Architecture is the answer to that question, not a menu selection (§13.6 — strip the final cause and pattern is mere shape; architecture without telos is shape without direction). This move is derivation; "architecture is choice" is the failure it rules out.

4. *Generate the minimal story set that would prove the architecture serves the telos.* Not a backlog. The smallest set of stories whose passing constitutes an argument that this architecture achieves this telos.

5. *Run them. Route each failure by layer.* (See G4.)

The loop is the run-forward of §13.13: the agent builds the programme so it anticipates rather than absorbs — the architecture is staked to see the problem coming, and the stories are where the anticipation gets tested against the world.

---

**G2 — Commit, not freeze.**

"Freeze" imports false permanence. Wrong posture for telos and architecture. The correct posture is git-commit semantics one layer up (rhetoric §2.19, §3.5 — commit-as-ratification, append-only, supersession-via-merge): commit to telos and architecture *with intent*. Default is hold. Amendment requires a deliberate act — supersession with evidence (§3.5), never drift. The frozen tier is operated *from*, not re-litigated (§2.5), but operated-from is not metaphysically permanent; it is a deliberate hold that a deliberate act can move.

Word-choice correction, not new logic. "Freeze" names a state nothing can move; "commit" names a state only an act can move. The architecture already runs on the second (§3.5); the first was the wrong word for it.

---

**G3 — Minimal-stories-as-proof is the tractable termination criterion.**

The story set is complete when a solid argument can be made that it proves the architecture serves the telos. Counter-arguments reveal gaps — a successful counter-argument is a missing story, named. This replaces "build until it's ready" with a measurable, arguable target: the stopping condition is *the proof closes*, not *the work feels done*.

The corpus had no stated stopping condition for "how many stories are enough." This stakes one.

Proof is still craft. "What counts as proof" is a felt judgment — calibration, practiced instinct, resists a measure (§11.6). No conflict: §11.6 governs the *how-much*; G3 stakes the *what* — the felt judgment now has a named object (does the set prove arch-serves-telos), where before it had none. The terminus stays felt; it stops being unanchored.

---

**G4 — The escalation discipline: failure-layer determines adjustment-layer.**

Every failure routes by which of the four primitives it instantiates (§8.6 — spec, substrate, craft, epistemic; the partition tiles all software problems).

*Spec failure* (intent→code broken, §8.1) and *substrate failure* (code→world broken, §8.4) escalate to architecture — possibly to a telos re-reading. These are alignment breaks: the build is aimed wrong, which can mean the design is wrong, which can mean the read of the telos was wrong.

*Craft failure* (intrinsic structure degraded, every bond intact) and *epistemic failure* (artifact→because broken, §8.2) stay local. Craft is fixed at the story level; epistemic is fixed at the information level. Architecture holds — the failure is in the artifact or the record, not the aim.

This is the §13.13 belt/core logic fused with the §8.6 partition. The protective belt absorbs anomalies; the hard core is protected by convention (§13.13). G4 says *which* anomalies the belt absorbs (craft, epistemic — local) and *which* reach the core (spec, substrate — architecture, telos). Neither §8 nor §13.13 states this join. §8 partitions the failures; §13.13 names belt vs. core; the wiring of the four onto the two is the stake here.

*Dominant collapse mode:* escalating a craft or epistemic failure to architecture. "We built it wrong" (craft) read as "we designed it wrong" (architecture). The belt anomaly mistaken for a core threat. The discipline is the guard against it: a local failure that triggers an architecture revision is the protective belt thickening to defend the core against pressure it was never under (§13.13 degenerative shape). The build that re-designs every time a module couples badly is degenerating, not improving.

---

**Debt is not a fifth primitive.**

The corpus is correct (§8.6, §8.11 — named debts are compositions, not peers). Debt is *accumulated [primitive]* — a temporal dimension running across the four, not a fifth alongside them. Route debt by naming which primitive it instantiates (§8.12 — decompose, then route each fraction). A debt does not enter the escalation loop as itself; it enters as the primitive it accumulated.

---

**Open.**

G3's "solid argument" inherits §11.6's open edge: what makes a proof solid resists a measure, and G3 does not close it — it names the object the felt judgment grips, no more.

G4's spec/substrate → architecture leg holds an unresolved residual: a spec or substrate failure *can* reach the telos read, but the rule does not say *when* it stops at architecture and when it goes all the way to re-reading the telos. The boundary between "design was wrong" and "the read of the telos was wrong" is genuinely open — same shape as §13.13's open question of what counts as a registrable anticipation vs. ad hoc absorption. Flag, not resolved.
