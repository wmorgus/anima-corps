Epistle 032 — Substrate.md: The Material Cause Doc
Topic: The corpus docs already instantiate the four-cause structure (Epistle 028) — but partially. The material-cause doc is missing. Telos.md's own derivation bridges name the gap by what they omit. Create substrate.md, migrate §6 agents into it, give agents and Bench (031) their proper home. A migration, not a supersession — claims keep their content, change their file. Same shape at the doc-architecture scale (§7.1 receipt).

**claim.** The corpus documents are already organized by the four causes they name (Epistle 028) — but the material-cause doc was never built. Build it: `corpora/anima/substrate.md`. The §6 agent block migrates into it. Bench (031) lands into it once ratified. The doc instantiates, at the scale of the corpus's own files, the partition Epistle 028 stakes for software artifacts and §13.6 stakes for architecture. The form of the docs becomes the claim of the docs.

**the four causes already organize the existing docs — minus one.** Map what exists onto Epistle 028's partition:
- **telos.md = final cause.** The zeroth-class doc (telos.md, opening). The why, the ruling-outs, the value ordering. Not a peer in the partition — the condition the other docs require to mean anything (Epistle 028: telos-primacy; §13.6). Already built, already named as off-the-scale.
- **logic.md = formal cause.** The conviction corpus — the architectural §-claims, the pattern that makes Anima THIS system. "The pattern that makes this system THIS system" is Epistle 028's formal-cause definition verbatim. logic.md is formal-cause territory and always was.
- **rhetoric.md = the doxa register.** The same commitments meeting conversation (telos.md bridge). Rhetorical decoration, argument shapes — adjacent to the partition, not inside M/E/F. Not a fourth cause; a presentation register.
- **corpus_vocab.md = definitional substrate.** The other corpora cite it for term-meaning (telos.md bridge). Definitional ground, cited-from. Sits under all four.

Three of the four causes have a doc. The missing one is material cause — **what the system is made of.** No doc answers it. The gap is not hidden: telos.md's own derivation bridges enumerate logic.md, rhetoric.md, corpus_vocab.md, ur-software — and stop. No substrate bridge. The bridge list is a map with the material-cause coordinate blank.

**§6 agents are material-cause content living in a formal-cause doc.** logic.md §6 (agent topology) is the misfile. logic.md is the conviction corpus — architectural claims, what the system IS and rules out (formal cause). Agents are what the system is *made of* (material cause, Epistle 028: "the substrate — what the system is actually made of"). The §6 block is material-cause content in a formal-cause doc. This is why the agents section reads heavy and mixed — not because the claims are wrong (they are not), but because their *home* is wrong. §6.12–§6.19 (Hermes, Mnemosyne, Pavel, Daedalus, Argus, Janus) are entries in an inventory of constituents, not architectural convictions. They belong where the inventory lives.

**substrate.md — the material-cause doc.** What the system is made of:
- **agent definitions** — the §6 agent block (§6.12–§6.19 and the agent-specific entries: telescoping occupancy, Hephaestus scope, non-slots). Migrated, not rewritten.
- **Bench** (Epistle 031) — the host, the VS Code fork the whole loop runs in. Lands here once ratified. Bench is the most material of materials: the concrete substrate (031: "the concrete place to run them"). Note the term collision held, not resolved: Bench is *host* (where humans and constellation co-locate, 031); Calliope is the *artifact store* (§4). Both are "substrate" in different registers — Bench the runtime substrate, Calliope the commitment substrate. substrate.md is the doc for the made-of; it houses Bench's definition and points to §4 for Calliope, which stays in logic.md as a formal-cause architectural claim. Flag: whether §4 (Calliope) is itself material-cause and should migrate too is open below.
- **constellation structure** — the topology-as-liquid-artifact framing (§6.4), the made-of-agents shape.

Doc format mirrors the four-cause pattern. Each agent entry answers the same five questions, made explicit as a template: **domain owned** · **harm-when-failed + harm-bearer** (the §6.1 license) · **name import** (§6.8, what obligation the name carries) · **occupant** (resolved / candidate / open) · **rules out**. The entries already carry this shape implicitly; substrate.md makes it the doc's spine.

**migration, not supersession — the load-bearing distinction.** The §-numbered claims do not change. §6.1's harm-distinctness, §6.12's Hermes domain, §6.18's Argus license — same content, same rules-out, same cross-references. Only the *file they live in* changes. This is not §3.10 supersession: supersession negates a predecessor and elevates a successor with the *because* for the move on record (telos.md ruling-out 6; §13.7). Nothing is negated here. No claim is replaced. The claims are relocated intact. A migration changes *where claims live*; a supersession changes *what they say or what they rule out*. The corpus versioning convention (§17, CLAUDE.md semver) is built for the latter and silent on the former. Stake the distinction so the move is not mis-recorded as a ratification event.

**VERSION implication — patch, not minor.** A minor bump is a ratification event: an epistle moves liquid → frozen into the corpus, a new frozen claim lands (CLAUDE.md semver). No new claim freezes here. A major bump supersedes a frozen §-claim, changing what the corpus rules out. Nothing's rules-out changes. The move is a clarification/correction to the arrangement of existing frozen artifacts — that is the patch definition. Probably patch. Flag: the convention does not explicitly name "doc reorganization" as a version event class at all — see open tension. The bridge-list amendment to telos.md (below) is additive, not a supersession of telos.md's frozen content; it does not lift the floor.

**telos.md derivation bridges gain an entry.** Once substrate.md exists, telos.md's bridge list adds:
`→ corpora/anima/substrate.md — the material register; what the system is made of (agents, host, constellation).`
This is additive. The bridge list is already explicitly open — it carries a "Planned: → composition.md" line (§1.16). Adding a bridge to a doc that now exists is the same move, completed rather than planned. A small telos.md amendment, not a rewrite. It closes the blank coordinate the omission named.

**logic.md becomes the doc it was always meant to be.** With §6 migrated out, logic.md is the conviction/architecture corpus, clean:
- §1–§5 — ratification architecture (ontology, liquidity, governance, Calliope-as-store, topology principle).
- §7–§9 — self-resonance, diagnostic posture, inferential UI.
- §10–§13 — power/ethics, the information poet, adjacent work, the epistemic frame and causal structure.
- §14 — the bet surface.
- §15–§16 — open tensions, known gaps.

The agent *implementation inventory* is gone; the agent *topology principles* (§6.0–§6.11 — the slot-license logic, harm-distinctness, thin-agent, concept-ownership) are the genuinely open question below. logic.md becomes formal cause throughout: what the system IS, not what it's made of.

**§7.1 self-resonance — the receipt.** §7.1: the same shape recurs at every scale — artifact, agent, pipeline, the paper itself. Add a scale: **the doc architecture.** The corpus is organized by the same four causes it names as the structure of software artifacts (Epistle 028) and of architecture (§13.6). The form of the docs instantiates the claim of the docs. This is §7.2's checkable evidence the abstraction is at the joints — an abstraction wrong at the joints could not replicate cleanly down to the filing of its own corpus. Not designed-in; surfaced by following the partition to the docs that hold it. Same shape three scales: §13.6 architecture, Epistle 028 artifact, this doc-architecture. The receipt is that building substrate.md was forced by the partition, not chosen for tidiness — the gap announced itself through telos.md's blank bridge.

**open tensions.**

- **VERSION semantics for a migration event — genuinely open.** The semver convention (patch/minor/major) is defined over *frozen-artifact content*: patch corrects, minor ratifies, major supersedes. A doc reorganization that moves frozen claims between files without touching their content fits none cleanly. Patch is the closest read (clarification to existing frozen artifacts, no claim changed) but "clarification to an artifact" is not obviously "move an artifact to a new file." The convention has no event class for re-filing. Don't know yet. Flag: resolve whether migration needs its own version semantics or folds into patch *before* committing the move, so the version record is honest about what happened.

- **which §-sections beyond §6 belong in substrate.md.** §6a (agent context architecture — the four tiers an agent reasons from, the delivery-mechanism contradictions) is a candidate: it is about what agents *run in* and *reason from at init*, arguably made-of content, not conviction claims about the architecture. But §6a is also half about *contradictions* (§6a.5–§6a.8 — the implementation outrunning a ratified decision) and named *silences* (§6a.9–§6a.10) — that reads as formal-cause/open-tension content, belonging with logic.md's §15–§16. §6a may split across the migration: the tier *definitions* (§6a.1–§6a.4, what agents are made to reason from) to substrate.md, the *contradictions and silences* staying in logic.md as open architecture. And §4 (Calliope) — the commitment substrate — is itself material-cause by Epistle 028's reading ("the data at rest, the running system"). Whether Calliope migrates too, or stays in logic.md because it is an architectural *principle* (one append-only store, single API, §4.1) more than an inventory of made-of-stuff, is the same host-vs-system tension 031 holds, surfaced one level up at the doc scale. Named, not resolved.

- **the composition.md gap.** telos.md (§1.16) names composition.md as planned, still unbuilt — the compositionality surface the orphan-check reasons over. The substrate refactor surfaces a placement question it did not before: is compositionality a conviction claim (how artifacts *must* compose — formal cause, logic.md) or a description of the composed substrate (what the composition *is made of* — material cause, substrate.md)? The four-cause map does not pre-decide it. Flag: building substrate.md gives composition.md a second possible home; decide which cause composition serves before building it, or it inherits the same misfile §6 just escaped.
