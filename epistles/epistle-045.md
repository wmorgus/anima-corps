Epistle 045 — The Face Is Configuration, Not an Agent
Topic: §6.12a stakes Ari as the face Anima wears in the dojo, not a constellation entry. This epistle stakes the generalization: a face is a named persona plus an intake-depth configuration on Hermes, and any host context can configure one. The consequence is that Hermes's intake depth becomes configurable, and Option B (Hermes absorbs intake) follows — not as a new design choice, but as the only reading that keeps §6.12a's face/agent distinction intact.

---

**The face concept generalizes; Ari is one instance.**

§6.12a is explicit: Ari is a FACE, not a constellation entry — the persona the system wears in the dojo before the relay chain engages. The load-bearing word is *face*. Ari is the dojo's instance of it: a name (*phronesis*), a cultivation-specific intake posture, Hermes underneath. §6.12b confirms the shape — the dojo face and the orchestration authority are "two expressions of one telos authority," not two agents. The face is a register Hermes operates in, not a being that operates Hermes.

Once the face is named as a configuration rather than an agent, it generalizes by force. A Slack-based CL assistant is the face Anima wears in that context. It is not a new agent class. It is a named persona, a configured intake posture, and Hermes carrying the request underneath — the same three parts Ari has, fitted to a different surface. The generalization is not a new claim. It is what §6.12a already commits to, read at one more context.

**Intake depth is a Hermes configuration.**

The current CLI goes straight to `HermesAgent.run(task)`. That is Hermes at shallow intake depth — the task arrives already formed, Hermes routes it. The dojo runs Hermes at a different depth: Ari holds the conversation, cultivates the because-chain, clears the human only at telos-readiness (§6.12a). Same agent, same hermeneutic obligation (§6.12 — carry meaning across the boundary without distortion), different depth at which meaning gets carried.

Intake depth is therefore the configurable axis, and it has at least three settings:

- *Shallow* — the default CLI. The task arrives formed; Hermes routes.
- *Cultivating* — the dojo. Hermes holds the conversation at depth before routing, surfaces the because-chain. This is Ari.
- *Face-configured* — an external host. Hermes adopts a named persona with an intake style fitted to the context, cultivating or shallow depending on the face's purpose.

A face is system-prompt-level persona plus an intake-depth setting. The host invokes `anima --face socrates` (or equivalent config); Hermes loads the face's persona and intake depth from a Calliope `prompt-*` artifact. No new agent class is introduced, because none is needed — the intake capability was always Hermes's, and the face is the configuration that selects how deep it runs.

**Option B is forced, not chosen.**

Pulling intake into the CLI as a separate mode — a distinct intake agent the CLI invokes alongside Hermes — re-introduces the exact face/agent confusion §6.12a was written to resolve. If "the dojo has cultivation" became "there is a cultivation agent," the corpus would carry a constellation entry §6.12a explicitly ruled out. The generalization makes this concrete: every host context would breed its own intake agent, and the mesh §5.1 rules out would reassemble one face at a time.

Option B — Hermes absorbs intake, intake depth is a configuration on the one front door — is the only reading that survives §6.12a. Ari as a dojo face does not mean "dojo-only intake capability." It means the dojo has a named face whose intake depth is set to cultivating. The intake capability is Hermes's; the face is the name and persona and depth-setting for one context. This mirrors Bench's own shape — "CLI is the spine; UI is a face on it" — at the intake layer: Hermes is the spine, the face is a configuration rendered on it, never a replacement for it.

**The sock puppet is the honest form.**

A face is a sock puppet: transparently a face. Anima does not hide that it is Anima — it wears a character fitted to the context. This is honest under §1.5 (do not import obligations you do not owe). A face that pretended to be a human would import the social obligations of a person Anima is not; a face that is openly Anima-in-a-persona imports none. The persona is a register, declared, not a disguise.

The face name and persona should fit the host's culture, not be prescribed by the corpus. Socrates is a directional example for a CL Slack context, character to be decided by the people whose culture it joins. The corpus stakes the mechanism — named persona plus intake depth on Hermes — and stops there; which character fits CL's Slack is a human call, not a corpus claim.

Socrates as the example name is not arbitrary. §6.12 records that "Socrates" was tried as a name for Hermes and superseded — Socrates teaches within a tradition, Hermes carries meaning across traditions, and the function was evicted from the front-door agent. That eviction is exactly what makes Socrates available as a *face*. The teaching register that does not belong to Hermes-the-agent can be worn as a face Hermes operates. The name's own history demonstrates the face/agent distinction this epistle stakes.

**Open.**

- *Face identity's home.* Is a face a `prompt-*` artifact, or does it need a dedicated Calliope type? A face carries persona, intake depth, and likely a relay-provenance handle — that may exceed what a prompt artifact holds. The shape of the configuration determines the type; the shape is not yet pinned.

- *Load mechanism.* How does Hermes acquire a face at invocation — config flag, environment variable, or a Calliope query at startup? §3.3 externality favors a startup query (the face is pulled from the store, not pushed by the caller), but the corpus has not staked it.

- *Face provenance on the relay.* Does a face get its own relay-record identifier? The relay should know which face opened it — provenance argues yes. Unstaked, but leaning.

- *Status against §6.12a.* Is this a derivation from an already-staked claim, or does it require a §6.12a amendment? The face/agent distinction is §6.12a's; the generalization to arbitrary host contexts and the intake-depth axis are new. Whether that crosses from derivation into amendment is the question shitcorping has to rule on.
